transom

transom lets a program ask a person a question and get the answer back, without a chat.

The question arrives on the person's phone as a notification they can answer from the notification itself. It also waits in an inbox, in the app and on the web, until someone answers it or it expires. The answer goes back to the program that asked, through a waiting HTTP request, an event stream, an MCP tool, or a signed webhook. transom also sends one-way notifications, such as alerts.

What it is

  • A server you run yourself, on Redis. It holds no passwords or API keys: people and agents sign in with an identity provider you already run, and transom checks their tokens.
  • An HTTP API that curl can use, and an MCP server for AI agents.
  • A web inbox, and an Android app published as a signed APK on GitHub releases, which Obtainium can track.
  • A wake-up gateway at wake.transom.sh that tells the app to sync. It never sees what a message says.

The source, the design, and the releases are on GitHub at github.com/chrisguidry/transom.
